## The blocking defect — B4

`mixle.inference.glm()` computes the coefficient covariance as `pinv(X'WX)`. Because
`cond(X'WX) = cond(X)^2`, the pseudo-inverse's default cutoff silently truncates on designs
whose own conditioning is unremarkable.

Reproduced by the report author independently, n=400, two near-collinear predictors:

| `cond(X)` | max relative error in standard errors |
|---|---|
| 2.0e2 | 5.5e-12 |
| 2.0e5 | 3.6e-06 |
| 2.0e6 | 7.2e-04 |
| 2.0e7 | 5.9e-03 |
| **2.0e8** | **1.0 (100%)** |

At `cond(X) = 1.99e8`:

- statsmodels standard errors: `[0.0047, 4.66e5, 4.66e5]`
- mixle standard errors: `[0.0047, 0.0023, 0.0023]` — **eight orders of magnitude too small**
- mixle coefficients: `+14410`, `-14410` (truth `1.0`, `-0.5`), reported with se `0.0023`, hence
  overwhelmingly "significant"; statsmodels correctly gives p = 0.79 for both
- mixle reports `converged=True`, `rank=3` (claiming full rank), and emits **zero warnings**

This is a silent wrong answer that a user publishes. `glm` is in `mixle.inference.__all__`,
called with its documented signature, and `maturity_of` resolves the surface to **stable**.
The maturity-tier defence does not apply.

**Suggested fix:** form the covariance from a QR or SVD factorization of the weighted design
matrix rather than a pseudo-inverse of the normal-equations matrix, and report `rank` from that
factorization so a rank-deficient design is stated rather than concealed.

## Majors worth deciding on before tagging

Not release-blocking on correctness, but they are on the paths a new user meets first:

- **B13 / B14** — the README headline `solve(teacher, inputs)` example produces a student that
  escalates 100% of requests while reporting `promoted=True`, and its `report()` advertises a 7%
  escalation rate that the live path contradicts. The documented `answered_slice` key is `None`.
- **B9** — `mixle.propose(DataFrame)` models the **column names**: a 200x3 numeric frame returns
  `CategoricalDistribution({'a': 0.5, 'b': 0.25, 'c': 0.25})`, zero warnings, certificate
  `succeeded`, after both real candidates failed to score. `optimize()` handles the same frame
  correctly, so the two top-level entry points disagree and the automatic one is wrong.
- **B8** — `propose()` selects a degenerate near-Dirac `GeneralizedPareto` (scale 8.8e-26) as
  best model for a count column, reporting a *positive* held-out log-density. mixle already has
  the machinery to catch this (`calibrate=` returns the worst PIT error measured), but
  `propose()` ranks on mean log-density alone and never consults it.
- **B5** — an undocumented default ridge of `1e-6 * mean(diag(Sigma))` in the multivariate
  Gaussian estimators.
- **B6** — a deployed artifact containing a `MultivariateGaussianDistribution` fails to load
  across scipy versions that both satisfy the declared floor.
- **B7** — `restarts="auto"` returns a mixture 57.96 nats below the optimum on Old Faithful.
- **B2** — the variance M-step's `E[x^2]-E[x]^2` form is not shift-invariant; the scale collapses
  to the internal floor under large offsets. Not silent: `numerical_repairs()` reports
  `variance-floored(0 -> 1e-08)`.

`propose()` accounts for four of the fourteen. The pattern is consistent and matches the defect
class already recorded for this release: **the automatic entry point fails open where the rest of
the library fails closed.**

## Recommendation

1. Fix **B4** — it is the only true correctness blocker, and it is cheap.
2. Decide on **B13/B14** and **B9**: a release whose README quickstart misreports its own
   headline metric is a credibility problem for a library whose pitch is ergonomics.
3. Everything else to 0.8.1, with `propose()`'s fail-open behavior tracked as one item rather
   than four.
4. Obtain genuinely independent evidence for E4 and E14, or amend those rows explicitly.
