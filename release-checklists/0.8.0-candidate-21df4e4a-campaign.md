## The pattern: reviewing the fixes themselves caught two more gaps

After all ten fixes landed, an independent agent adversarially reviewed the full production-code
diff, specifically hunting for the failure mode that has recurred across this release: a guard or
clamp scoped narrower or wider than the actual defect. It found two real issues, both confirmed by
reproducing them against the actual library code:

1. The `GeneralizedPareto` fix's own accumulator-side relevance pre-check decided whether to carry
   the training data's max forward from RAW moments alone, invisible to a `pseudo_count` prior
   blended in afterward by `estimate()`. A strong enough prior could still push the blended shape
   negative and reintroduce the identical self-inconsistent-fit crash the fix was written to
   eliminate.
2. The `propose()` rescue mechanism excused a field's `-inf` held-out score as an unseen
   categorical label based only on the leaf distribution's type, never checking that the `-inf`
   actually came from the leaf. An `OptionalDistribution`-wrapped field fit with `p==0` (no missing
   rows in training — an entirely ordinary outcome) independently scores a genuinely MISSING
   held-out value at `-inf` too, and was silently excused under the same "unseen in training"
   diagnosis, masking a real missing-value generalization failure.

Both were fixed with their own regression tests, each proven to fail against the pre-review code
and pass after. The `GeneralizedPareto` fix needed a second iteration: the first attempt (always
carry the max, unconditionally) closed the gap but broke a pre-existing pinned cross-family
invariant (`campaign4_shift_sweep_test.py::test_ordinary_data_never_activates_the_anchored_track`
— well-conditioned, no-prior data must return the historical plain tuple, byte for byte), caught by
the full core tier, not by the fix's own targeted tests. See D-0205 for the full account.

## Confirmed blocking

**[T1-01] GeneralizedParetoEstimator: EM loop crashes on realistic negative-shape data**

- Surface: `mixle.inference.optimize`/`fit` with `mixle.stats.GeneralizedParetoEstimator`
- A shape<0 method-of-moments single-shot fit can produce a model whose implied support upper
  bound sits below the training data's own max — a real, ~15% likely artifact for negative-shape
  MoM at ordinary sample sizes. The next EM iteration then re-validates the SAME training data
  against that self-inconsistent model and raises. Swept 60 seeds × n ∈ {20,50,100,300} against a
  genuine `GeneralizedParetoDistribution(1.0, -0.3, loc=0.0)`: 37/240 trials produced a
  support-violating single-shot fit, and `optimize(..., max_its=3)` crashed with the identical
  `ValueError` in every one of those 37.
- Fix: track the largest raw observation alongside the accumulated moments; when the fitted shape
  is negative and would exclude it, raise `scale` (never `shape`) to the smallest value restoring
  support consistency, disclosed via `numerical_repairs()`. Second-pass fix: only elide carrying
  the max for a no-prior estimator, since a `pseudo_count` prior's blend is invisible to the raw
  pre-check and can independently need the clamp.

**[T1-02] pd.NA-fit OptionalDistribution cannot score or re-encode its own training data**

- Surface: `mixle.inference.optimize(data, out=None)` auto-inference → `OptionalDistribution`, for
  data from a pandas nullable-extension (`Float64`/`Int64`/`boolean`) Series
- A model auto-fit from a `pd.NA`-carrying column has its wrapper's `missing_value` normalized to
  `None`, not `pd.NA`. `log_density(pd.NA)` and re-encoding the SAME training data both crash with
  `TypeError`. The NaN-spelled equivalent round-trips perfectly.
- Fix: the missing-value sentinel is now pd.NA-aware across the same three call sites unified for
  the analogous dtype-consistency defect in campaign four (`normalize_input`,
  `_data_records_for_encoding`, `Model`/`propose` entry), plus `OptionalDistribution`'s own
  encoding.

**[T1-03] Dirty-cell -inf memorization bug reopens for string-typed numeric columns**

- Surface: `mixle.inference.optimize` auto-inference column-typing
- D-0203's fix covered a float-typed column with one stray non-numeric cell. This is the single
  most common real trigger for the identical outcome: pandas coerces an ENTIRE numeric column to
  object/str dtype the moment any one row fails float parsing (standard pandas behavior). At every
  cardinality swept (n ∈ {20,50,80,120,200,300}), 30/30 held-out same-distribution values scored
  `-inf` — not an edge case, the default outcome for any string-typed numeric column.
- Fix: auto-inference's column-typing now recognizes an all-numeric-looking string column as
  continuous, extending the same mechanism the earlier fix used for the float-column variant.

**[T4-01] TreeHiddenMarkovEstimator silently fits NaN-poisoned parameters on shallow-only corpora**

- Surface: `mixle.stats.latent.tree_hidden_markov_model.TreeHiddenMarkovEstimator`, via `optimize()`
- Training on a corpus that never reaches some tree depth (an ordinary, legitimate training shape)
  produces a `RuntimeWarning: invalid value encountered in divide` that `optimize()` never
  surfaces; the fitted model's own attributes look finite, but `log_density()` on a later,
  out-of-sample tree that DOES reach that depth silently returns `nan`. A related guard fires
  correctly when the deeper tree shares the SAME fitting batch — but not in the ordinary
  train-then-score usage pattern.
- Fix: the zero-evidence transition row is no longer folded into the poisoned division at its
  source, for both the numba and non-numba paths.

## Confirmed major

- **[T1-04]** `GammaEstimator`'s hard shape-parameter ceiling (1e12, binds at near-zero coefficient
  of variation) is never disclosed via `numerical_repairs()`/`fit_provenance()`, unlike the
  meticulously-disclosed analogous floor in `GaussianEstimator`. Fixed: disclosed identically.
- **[T2-01]** `propose()`'s verified frontier silently collapsed to the fully unverified fallback
  for the WHOLE joint model whenever any single field was identifier-like/high-cardinality or an
  unrecognized dtype (e.g. `datetime64`) — extremely common real tabular column shapes. Fixed: the
  offending field is now excluded from just its own contribution to the aggregate score, disclosed
  by name, while the rest of the candidate is still verified and ranked.
- **[T3-01]** A fitted distribution's `numerical_repairs()` silently returned empty after
  `Model.deploy()`/`Model.load()`, even when a repair genuinely occurred and stayed in effect —
  `_fit_provenance` had an envelope re-attachment fix for this exact reason;
  `_numerical_repairs` never got the equivalent treatment. Fixed: mirrored.
- **[T3-02]** README's second Quickstart example (`mixle.task.solve`) crashes with `ImportError` on
  the documented base install, because its default student is a torch MLP and nothing in that part
  of the README says so — unlike the very next example. Fixed: disclosed inline.
- **[T3-03]** `ProbabilityDistribution.to_json()`/`from_json()` — documented as a safe
  serialization route — silently produced a write-only artifact for at least
  `VonMisesDistribution`: `to_json()` succeeded with no warning; `from_json()` on the result failed
  in a later process. The module-level `dump_models(verify=True)` already refuses this case. Fixed:
  `to_json()` now performs the same read-back verification.
- **[T4-02]** `LDAEstimator`'s default alpha solver diverges to infinity for the large majority of
  realistic small-to-moderate corpora, not just adversarial ones, with a misleading error message
  implying `max_alpha_iter` would help when it provably cannot. Fixed: the message now names the
  estimator's own working escape hatches; the solver's fail-closed design itself is a deliberate,
  recorded decision (D-0052) left as-is, not unilaterally reversed by this fix.
