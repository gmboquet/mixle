## The pattern: fixing findings reopened an earlier fix, caught by reviewing the fix itself, not by a tester

After all nine fixes landed, an independent agent adversarially reviewed the full production-code
diff (a practice introduced in campaign five's fix wave after it caught two gaps the same way). It
found one confirmed-blocking issue: the `_unseen_label_rescue` fix in this wave introduced a
corrected top-level field-path mapping and switched its own call site to it, but a SIBLING function
in the same file — `_refresh_frozen_identifier_leaves`, campaign five's fix for `propose(fit=True)`'s
final-refit crash, extended in this wave to also handle dict-shaped rows — was left calling with the
OLD, leaf-level mapping. That function's own length-mismatch guard then always failed the moment any
field decomposed into more than one leaf (a sequence field, for instance), silently no-opping and
reopening the exact crash three separate fixes across two campaigns were supposed to have closed,
for any schema combining an identifier field with a sequence field. See D-0206 for the full account,
including two more defects (a `certify()` `KeyError` on dict rows, a `LookbackHiddenMarkovModel`
zero-sequence-corpus crash) found incidentally while fixing the campaign's own findings and fixed
by the release owner directly.

## Confirmed major

- **[T1-01/T1-02]** `GeneralizedParetoEstimator`'s prior/support-consistency machinery (already the
  site of two D-0205 findings) produced two more gaps: reassigning `.loc` after building an
  estimator with `dist.estimator(pseudo_count=...)` silently corrupted the frozen prior's absolute
  moments; `combine()` on a foreign/plain-tuple partial (no tracked observation max) silently
  defeated the prior-carrying support-consistency clamp entirely, reproducing the original T1-01
  crash class end to end with no disclosure. Fixed: `.loc` is now a property whose setter
  re-derives the prior's frozen moments for the new threshold; a foreign combine on a prior-carrying
  accumulator now discloses via `numerical_repairs()` that support-consistency could not be
  verified.
- **[T2-01]** `propose()`'s unseen-label-rescue disclosure (fixed twice before) misnamed the
  excluded field — and fabricated its held-out-row count — whenever a sequence/composite-decomposed
  field preceded the real culprit in column order. Fixed by correctly mapping top-level candidate
  children to field paths. See "the pattern" above for what this fix's own gap reopened.
- **[T3-01]** `propose(fit=True)` still crashed with the previously-fixed error when the winning
  candidate was a dict-shaped `RecordEstimator` rather than `CompositeEstimator`, since campaign
  five's fix only recognized the latter. Fixed: extended to `RecordEstimator`. Incidentally found:
  `certify()`'s data-dependent verification indexed dict rows with a bare integer, raising
  `KeyError` (not the `IndexError`/`TypeError` its except clause tolerated) — every dict-shaped
  `propose(fit=True)` call's certificate silently failed regardless of fit quality. Both fixed.
- **[T3-02]** `optimize(delta=None, max_its=N)` could silently run fewer than `N` iterations on a
  rejected/non-improving step — changed the outcome of the README's own `production_example.py`
  checkpointing walkthrough. Fixed: disclosed via the existing capped-unconverged-fit mechanism.
- **[T4-01]** `LDAEstimator`'s alpha-divergence detector had a floating-point boundary gap: several
  ordinary topic counts fell back to the pre-fix "needs more iterations" message even though the
  solve was genuinely diverging (directly disproved by raising the iteration cap 200x with no
  effect). Fixed: widened the boundary check with a tolerance sized to observed floating-point
  noise.
- **[T4-02]** The shared low-level `seq_initialize` raised a raw `IndexError` on a truly-empty
  (zero-sequence) corpus, distinct from the individually-empty-sequences case D-0203/D-0204 already
  handle. Fixed: the existing high-level guard now reaches the low-level entry point. Incidentally
  found: `LookbackHiddenMarkovModelEstimator`'s own `seq_update`/`seq_posterior` independently
  crashed on the same corpus shape via unrelated dead code (`max_len = sz.max()`, never read since
  introduction) — removed.
- **[T4-03]** Auto-inference silently reclassified `+inf`/`-inf` in a numeric column as a fitted
  missingness indicator, contradicting `optimize()`'s own documented sentinel list. Fixed: disclosed
  via a warning at fit time.

## Documentation and minor findings reported

- (T1) `glm()`'s docstring states HC1/HC2/HC3 robust covariance estimators "are refused on a
  saturated fit", but this only holds for fixed-dispersion families.
- (T2) The `Model` returned by `propose()`/`optimize()` has no per-row scoring method accepting a
  dict or pandas row directly.
- (T2) README's `solve()` quickstart snippet is not literally runnable, unlike the `optimize()`
  snippet immediately above it.
- (T3) The `to_json()` round-trip-safety fix correctly generalized past `VonMisesDistribution` to
  the base class.
- (T4) `propose()`'s per-field unseen-label rescue does not apply uniformly across every candidate
  generator.
