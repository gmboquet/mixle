# Mixle 0.8.0 local preflight evidence

This file has two rounds. The 2026-08-04 round is current. The 2026-07-21 round is retained below it for
lineage and is **superseded**: it ran on CPython 3.14.5, which is outside the declared 3.11/3.12 support
matrix, so its numbers were never evidence for this release even when they were fresh. Several of them had
also gone stale by 2026-08-04 (file counts, module counts, artifact digests).

Neither round is final release sign-off. No tag was created and no artifact was published.

### One thing this round found

`registry_test.py::RegistryTest::test_concurrent_register_with_auto_ids_does_not_collide` and
`::test_concurrent_register_with_distinct_ids_does_not_drop_index_entries` **both failed once** inside a
15-file parallel batch, then passed on an immediate re-run of the identical batch and in five consecutive
isolated runs of `registry_test.py` (23 passed each time). Two concurrency tests that fail only under load are
what an intermittent hosted failure looks like before it is understood. They are the first thing the repeated
randomized campaign should target; this is recorded rather than dismissed as noise.

### Concurrent edits during this round

A separate edit pass across `examples/**`, `docs/**`, `mixle/tests/distill_methods_test.py`, and later
`mixle/stats/latent/hidden_markov.py` landed in this shared worktree between roughly 11:05 and 12:03 while
these checks were running. Consequences, recorded rather than smoothed over:

- Four `inputs[].sha256` values in `0.8.0-repro-bundle.json` drifted, which made `run_repro_entry.py` fail
  closed. `build_repro_bundle.py --write` regenerated exactly those four digests and nothing else, and all
  four local entries were then re-run and passed against the regenerated bundle.
- `check_public_claims.py` and two tests began failing on new unregistered claim prose in
  `examples/engine_benchmark_example.py` and a new docstring mention in
  `examples/vision_edge_distillation/verify_on_laptop.py`. Both repairs live outside this round's scope and
  are itemized at the end of `0.8.0.md`.
- The `mixle/` package tree was unchanged through the prose pass, then changed at about 12:00 when
  `mixle/stats/latent/hidden_markov.py` was edited. The manifest/drift batch was re-run after that edit and
  still passed, so the API, maturity, schema, and stable-signature manifests remain consistent with the tree.
- **Anything in this round that content-addresses `examples/**` or `docs/**` — the reproduction bundle above
  all — is only as current as the last edit.** Re-run it before treating it as candidate evidence.
