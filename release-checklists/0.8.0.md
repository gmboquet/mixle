# Mixle 0.8.0 release-preparation checklist

This is the authoritative package-local checklist for 0.8.0. The release contract is defined by
`docs/release-readiness.rst`; supporting decisions, risks, review protocols, and stage gates are in this
directory. The former link to an ignored `notes/` worklist was removed because a release process must be
available from a clean clone.

Preparation branch: `release-prep/0.8.0` → `release/0.8.0`.

**Do not create `v0.8.0`, publish artifacts, merge the preparation PR, or mark final sign-off while any
pre-publication `IMPLEMENTED`, `HOSTED`, or `EXTERNAL` gate below remains.** `POST-RELEASE` rows are mandatory follow-up
checks after publication; by definition they neither authorize nor block the first publication. The tag is
deliberately outside this work.

## Status vocabulary

- `IMPLEMENTED` — implementation exists and has local development checks, but this is not
  candidate-bound release evidence and does not clear the gate.
- `DONE` — a schema-validated receipt records the exact candidate SHA, command, measured result,
  and date.
- `HOSTED` — implementation exists; the exact final commit must pass the named hosted job.
- `EXTERNAL` — requires a human reviewer, external user, registry, or designated hardware.
- `EXCLUDED` — claim or operation is intentionally omitted, with the limitation stated.
- `POST-RELEASE` — can run only after publication.

The release-owner transition is: close every pre-publication gate → approve the exact
`release/0.8.0` tip → create its signed annotated `v0.8.0` tag → publish the GitHub Release. The publish
workflow then independently re-verifies the version, signed tag, exact release-branch tip, required check
runs, and artifact digests before Trusted Publishing. A successful upload changes the applicable
`POST-RELEASE` rows from pending follow-up to blocking completion work; failure of a post-release check
requires the documented yank-or-patch-forward decision.

Local validation commands are individually capped at 30 seconds. Broad suites and the full Sphinx build belong
in hosted CI; timing out locally is not converted into a pass.
