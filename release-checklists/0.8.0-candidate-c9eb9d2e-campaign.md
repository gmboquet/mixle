## Two defects in the HANDOUT itself, found by this campaign

Neither is a code defect; both would mislead a real external tester and must be carried into the
next candidate's brief.

1. **The brief's Role B recipe starts `python -m venv v`.** On the build machine the default
   `python3` is 3.14.5, which the wheel correctly refuses (`Requires-Python: <3.13,>=3.11`), so the
   documented first line produces an environment the artifact cannot install into. The recipe must
   name a supported interpreter explicitly.
2. **`source_content_sha256` means two different things under one key name.** In the wheel it
   digests the packaged subset (816 files); in the sdist's copy of the same provenance record it
   digests the whole build tree (2028 files). The values therefore differ legitimately, and anyone
   diffing that field across the two artifacts sees a mismatch that is not one. The sdist separately
   carries `sdist_content_sha256` equal to the wheel's `source_content_sha256`, which is the field
   that actually cross-checks. Either disambiguate the key or say this in the brief.

Also recorded, not a defect: a tester's base install resolved numpy 2.5.2 / scipy 1.18.1 -- newer
than the reproduction bundle's pinned 2.4.6 / 1.17.1 -- and the base install pulled only numpy and
scipy, as the brief promises. The pins bind the replay role, not the install contract.
