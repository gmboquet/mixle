## Real defects (wrong or misleading results an ordinary user can reach)

### P01-F02 · PoissonDistribution.entropy() and NegativeBinomialDistribution.entropy() allocate one array up to the upper quantile (unbounded memory; MemoryError at large lambda)
**Pass 01 (univariate distributions and estimators).** Surface: `mixle.stats.PoissonDistribution.entropy (poisson.py:354-357), mixle.stats.NegativeBinomialDistribution.entropy (negative_binomial.py:270-273)`

**Observed:** Peak allocation scales at ~32 bytes per unit of lambda (r): 3.6 MB at 1e5, 33 MB at 1e6, 324 MB at 1e7, 3.21 GB at 1e8 (1.4 s), did not finish in 60 s at 1e12 (thrashing), MemoryError at 1e15. Returned values are correct where it completes (10.629 at 1e8 = 0.5*ln(2*pi*e*lambda)). All other Poisson/NegBin methods at r up to 1e15 run in < 0.01 s.

**Expected:** Entropy computed in bounded memory (block-summed, or Gaussian/Euler-Maclaurin tail), as 0.8.1 did for LogSeries; or a clear error/bound. lambda=1e8..1e10 is a constructible, sampleable, cdf-able parameter.

**Reproduction:**
```
import tracemalloc
from mixle.stats import PoissonDistribution, NegativeBinomialDistribution
tracemalloc.start(); PoissonDistribution(1e8).entropy(); print(tracemalloc.get_traced_memory()[1]/1e9, 'GB')   # ~3.2 GB
tracemalloc.reset_peak(); NegativeBinomialDistribution(1e8, 0.5).entropy(); print(tracemalloc.get_traced_memory()[1]/1e9, 'GB')   # ~3.2 GB
PoissonDistribution(1e15).entropy()   # MemoryError: Unable to allocate 7.11 PiB for an array with shape (1000001264911106,)
```

**Notes:** Identical failure mode to the one the 0.8.1 changelog describes as the cause of every CI runner kill ('allocated one array up to the quantile (226 GiB ...)'), fixed only for LogSeries. lambda >= 1e9 will OOM a 16 GB machine.

### P03-F04 · fit_provenance().objective reports 'map' for prior-free top-level Composite/Optional/Sequence estimators; fused E-step path is silently disabled for them
**Pass 03 (the inference loop (optimize / fit / propose)).** Surface: `mixle.inference.optimize / fit objective='auto' resolution (_resolve_objective) with CompositeEstimator, OptionalEstimator, SequenceEstimator as the top-level estimator; FitProvenance.objective / .algorithm`

**Observed:** CompositeEstimator.get_prior() returns [None, None] (OptionalEstimator/SequenceEstimator return (None, None)); _resolve_objective tests 'get_prior() is not None' and returns 'map'.
