# 0.8.0 External Use-Case Intake (Worklist E14.4)

**Status: template.** E14.4 asks for **one real use case**: the 0.8.0 RC applied to **data the
maintainer did not design**. This is the intake the user (or the maintainer, on their behalf) fills
in. Copy to `release-checklists/0.8.0-use-case-<name>.md` and complete it.

**Rule amended 2026-08-22 by the release owner (D-0194).** The gate originally required an *external
user* and forbade substituting an internal demo. It now admits a **maintainer-executed** use case
built from the shipped examples and the `mixle-notebooks` corpus, provided that:

1. the analysis runs on **public data the maintainer did not design**, with its provenance recorded;
2. it executes against the **owner-confirmed candidate artifact** -- the wheel, verified by
   `mixle-reproduce`, never a source tree and never older bytes; and
3. the honesty rule below is applied in full, negative findings included.

What this substitution does **not** establish is recorded with it: the *data* is external, the *user*
is not, so it cannot evidence discoverability, documentation legibility to a newcomer, or anything
else that depends on the reader not having written the library.

**Honesty rule (acceptance):** findings feed docs and bug fixes, and **marketing must not
cherry-pick only the successes**. A use case where mixle *increased* work is as valuable a
finding as one where it reduced it, and must be recorded with the same prominence.
