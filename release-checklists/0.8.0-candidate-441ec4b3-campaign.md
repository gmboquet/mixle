Executed 2026-09-01/02 by the release owner's agent on the owner's standing order ("okay, finish
everything"), continuing after D-0208's fix wave closed candidate `31d8e1fd`'s campaign and

## Verdict

**NO-GO**, on the very first adversarial pass against a candidate that had already cleared build and

## The defect class this campaign's fix wave chased across three total rounds

The dominant confirmed finding was a single defect *mechanism* recurring across dozens of
independent call sites, not seven unrelated bugs: **squaring (or taking an outer product of) a raw
observation value before multiplying by its weight.** A weight of exactly `0.0` must contribute
exactly zero to a moment/statistic regardless of the paired value's magnitude, but computing
`value*value` (or `np.outer(value, value)`) *before* the weight is applied can overflow an ordinary
finite value to `+inf`, and `0.0 * inf = nan` under IEEE 754 — silently poisoning the whole reduction
for every *other*, legitimately-weighted observation folded alongside it. This is the same root
cause D-0208 (`AnchoredMomentTrack`) had already found and partially fixed in nine families; this
campaign found the pattern was never actually contained to `AnchoredMomentTrack` and recurred
independently in the plain (non-anchored) accumulator paths, the generated/stacked-mixture
acceleration path, and several hand-rolled per-family kernels that never route through either.

Because this single mechanism kept resurfacing in code adjacent to (but not covered by) each prior
round's fix, the fix wave required two full additional adversarial review rounds beyond the initial
campaign before a review round returned zero new confirmations of it:

- **Campaign (this file):** 7 findings confirmed against `441ec4b3` directly.
- **Round-1 review** (of the campaign's own fix wave): 12 further findings confirmed — the fix
  wave's actual scope was far narrower than the mechanism's true blast radius, missing several more
  accumulators' scalar `update()` paths, the generated stacked-statistics path's own row-masking,
  and multiple unrelated serialization/idempotency gaps surfaced along the way.
- **Round-2 review** (of round 1's fix wave): 17 further findings confirmed, zero refuted — an
  *increasing*, not decreasing, count across rounds, a departure from every prior campaign's fix-wave
  review pattern (D-0203 through D-0208 each converged to fewer findings per round). The largest of
  these was architectural rather than another instance of the same textual pattern: the row-level
  masking round 1 introduced (`_mask_statistic_rows_with_no_weight` in
  `mixle/stats/compute/declarations.py`) zeroed a row only when *no* stacked component wanted it at
  all — a row wanted by some but not all components kept its true, unmasked value, so a component
  with exactly zero weight on that row could still be poisoned by a *different* component's nonzero
  weight leaving the row unmasked. The identical per-row-only flaw had also been independently
  reimplemented in four hand-rolled `backend_stacked_sufficient_statistics` classmethods (Gumbel,
  GeneralizedPareto, Nakagami, Rician) with no downstream validation at all, so there it produced
  silent `nan` corruption rather than even a crash.

Full findings-by-round detail, root causes, and fixes are recorded in D-0209.

## What this evidence is and is not

Both the lens sessions and the verification sessions were performed by the release owner's agent —
the same party that built the artifacts and wrote the fixes. It is not independence from the
implementation author, and the "Two independent release testers" and "Reproducibility bundle and
independent replay" checklist rows stay open on that ground alone. Independently, any confirmed
blocking or major finding voids the candidate on its own terms: `441ec4b3` is superseded by the fix
wave's commit `448a20c6`, and both roles must run again against that replacement.

The increasing per-round confirmation count (7 -> 12 -> 17) is worth reading plainly rather than
explained away: it means this candidate's actual defect density in this specific mechanism was
badly underestimated by the campaign's own initial pass, and the true stopping condition — a review
round confirming zero new instances of the pattern — was not reached inside this arc. Whether a
further round is warranted before this candidate is re-submitted is recorded as an open decision in
D-0209 rather than assumed.
