# 0.8.1 Release Decision Log

Append-only record of 0.8.1 scope changes, waivers, API breaks, benchmark-methodology changes, and claim
changes. The rule is the same as `0.8.0-decisions.md`'s: **no release decision lives only in a PR thread
or a local note.** 0.8.1 is the 0.8.0 candidate tree released under a new version (D-0212), so
D-0001..D-0211 in `0.8.0-decisions.md` remain in force for it; this ledger continues the numbering.

Each entry records: **date · decision · alternatives · evidence · owner · reviewer · expiration · worklist**.

## D-0212 · 0.8.0 is skipped; the candidate tree ships as 0.8.1 with three checklist gates changed

- **Date:** 2026-09-07
- **Decision:** Version 0.8.0 is never published. The 0.8.0 candidate tree, exactly as prepared and
  verified under `0.8.0.md` (now `0.8.1.md`), plus the post-candidate fixes it already carried
  (the bounded log-series series, the independent-tester follow-ups, the shape-clamp disclosure,
  the README docs links, the rehearsal sdist fetch, D-0211), ships as **0.8.1** from branch
  `release/0.8.1` under tag `v0.8.1`. The 0.8.0-named history files (candidate campaigns, reviews,
  audits, `0.8.0-decisions.md`, `0.8.1-followups.md`) are kept unchanged as the record; the
  pipeline inputs (checklist, receipts, build and reproduction requirements, reproduction
  environment and bundle, extra-profile policy, license provenance) are renamed to 0.8.1 and
  every receipt is rebound to 0.8.1's evidence digest with its evidence text verbatim.
  Three checklist gates change for 0.8.1: (1) **"Two independent release testers" is replaced by
  "Ten AI adversarial reviews of the notebooks and examples"** -- ten passes by freshly started AI
  reviewers with no shared context, each given the exact candidate wheel, the `mixle-notebooks`
  corpus, and `examples/`, all ten green (every notebook and example executes on the candidate;
  every finding repaired with a regression test and independently re-run, or dispositioned here);
  (2) **"README reviewed for stale content"** is added; (3) **"Documentation reviewed for stale
  content"** is added. "Version is the final candidate version" and "Final release-owner sign-off"
  are reopened and must close on 0.8.1.
- **Alternatives considered:** (a) keep 0.8.0 and promote through the manual rehearsal record
  (D-0211) -- rejected by the owner after the re-cut's rehearsal failed on the TestPyPI digest as
  predicted: a release whose own rehearsal cannot pass under its number is not one to ship;
  (b) keep the external-tester gate -- the resources for two independent testers are not
  available for this cycle.
- **Evidence:** TestPyPI holds `mixle-0.8.0-py3-none-any.whl` and `mixle-0.8.0.tar.gz` from
  candidate `5207edcc` (run 34020725246); a package index never accepts a filename twice; artifact
  bytes depend on `SOURCE_DATE_EPOCH` (the commit timestamp), so the corrected candidate
  `9504451e`'s rehearsal (run 34043526388) failed on `published artifact digest differs` and on
  nothing else. 0.8.1 is absent from TestPyPI and PyPI at the time of this entry.
- **Owner:** release owner.
- **Reviewer:** accepted — Grant Boquet, release owner (order given in-session: skip 0.8.0, ship the tree as 0.8.1, replace the external-tester gate with ten AI adversarial reviews, add README and documentation stale-content review gates); 2026-09-07; https://github.com/gmboquet/mixle/actions/runs/34043526388
- **Expiration:** none. The three gates must close on the 0.8.1 candidate before `v0.8.1` is created.
- **Worklist:** release-checklists/0.8.1.md §11; release-checklists/0.8.1-followups.md.

## D-0213 · The ten adversarial reviews: blocking and documentation findings repaired in 0.8.1, the rest deferred to 0.8.2

- **Date:** 2026-09-07
- **Decision:** The ten AI adversarial review passes over the 0.8.1 candidate (wheel
  `mixle-0.8.1-py3-none-any.whl` sha256 `3190de82…`, tree `6040ea38`; reports and findings retained
  under `release-checklists/0.8.1-reviews/pass-NN/`) raised 134 findings: 7 blocking, 46 real, 54
  minor, 27 documentation, plus the execution fact over the corpus. 0.8.1 repairs every blocking
  finding and every documentation finding on the candidate, each with a regression test or a
  re-executed artifact and an independent re-run of the reviewer's reproduction (the repairs are
  listed under "Fixed by the ten adversarial reviews" in the CHANGELOG and, per finding, at the end
  of `release-checklists/0.8.2-followups.md`). Every real and minor finding, and one additional item
  found while repairing (the hidden-Markov initialization plateau, A-01), is deferred to a 0.8.2
  patch and recorded with the reviewer's reproduction in `release-checklists/0.8.2-followups.md`.
  This is the disposition the "Ten AI adversarial reviews" gate requires for a finding that is not
  repaired: 0.8.1 ships with 100 known, disclosed, un-fixed characteristics.
- **Alternatives considered:** (a) repair everything before tagging -- rejected by the owner:
  the real and minor findings are pre-existing characteristics of code the release-prep effort did
  not touch, and a second review cycle over 100 repairs would itself need re-review (the pass-22/23
  experience under D-0175 is the precedent for fresh repair code carrying defects); (b) ship with
  the blocking findings ledgered -- rejected: two of the seven are in code this release itself
  added (the log-series tail and the constrained MAP path), two are shipped examples printing a
  wrong result on their own path, one is a README snippet that raises on a current install, and
  two are shipped notebooks whose conclusion the candidate reverses.
- **Evidence:** `release-checklists/0.8.1-reviews/pass-NN/{report.md,findings.json}` (ten passes,
  every reproduction re-run in isolation by the reviewer); the corpus execution fact (131 notebooks:
  129 pass in the batch run, the two environment gaps -- pyspark/JDK, and a 30-minute batch cap on
  the certificate-embedding notebook whose manifest records a 51-minute solo cost -- pass solo;
  57 examples pass); regression tests `logseries_bounded_series_test.py::TailPastTheCapTest`,
  `constrained_map_certified_test.py`, `autoregressive_reduced_precision_test.py`,
  `mixture_kmeans_lloyd_init_test.py`; the reviewers' own reproductions re-run on the repaired tree
  (P04: `repro_F01.py`, `repro_decreasing5.py`, the `max_iter=1` command; P07: `atk_stock.py` on the
  repaired tree and on the 2026-08-10 tree; P01: the cdf/quantile values against an independent
  quadrature). The repairs change tracked bytes, so every earlier receipt in `0.8.1-receipts/` is
  rebound to this tree's evidence digest with its evidence text verbatim (the D-0212 procedure);
  what was re-measured on this tree the same day: the full test suite (16,234 passed, 319 skipped,
  0 failed), the Sphinx `-W` build, the four reproduction-bundle entries (arm64 and emulated
  x86-64, byte-exact), the 131-notebook corpus and the 57 examples.
- **Owner:** release owner.
- **Reviewer:** accepted — Grant Boquet, release owner (order given in-session: run the remaining adversarial passes, fix all blocking and documentation problems, document the other problems to be fixed in 0.8.2); 2026-09-07; https://github.com/gmboquet/mixle/tree/release/0.8.1/release-checklists/0.8.1-reviews
- **Expiration:** 0.8.2. Each item in `0.8.2-followups.md` is a known limitation of 0.8.1 until
  repaired.
- **Worklist:** release-checklists/0.8.2-followups.md; release-checklists/0.8.1.md §11 ("Ten AI
  adversarial reviews of the notebooks and examples").

## D-0214 · The signed 0.8.1 candidate is re-cut for two workflow-only fixes and promoted on a manual rehearsal record

- **Date:** 2026-09-07
- **Decision:** Candidate `73e67a2e` (tag `v0.8.1`, signed off, push CI green, dispatch run green,
  gate passed, prepare run 34091612593, rehearsal run 34093637518 green with the workflow's own
  record, 0.8.1 on TestPyPI at the candidate's exact digests) is re-cut because its automated
  promote (run 34094030813) was refused before any upload by the promote path itself: the
  rehearsal record's `prepare_run` is written from an environment string and
  `verify_rehearsal_record.py` compared it with an integer. The fix is workflow-only (the verifier
  matches a run id as text; the workflow writes an integer; the rehearsal step waits up to ten
  minutes for index propagation, which had also cost one re-dispatch), plus its test, this entry,
  and the ledger items A-04 and A-05. A new commit changes the build provenance and so the artifact
  bytes; TestPyPI cannot accept the 0.8.1 filenames again, so the re-cut's automated rehearsal
  fails on the digest comparison by design and the promote uses the manual rehearsal record
  (D-0211's path): the record states that TestPyPI holds the earlier candidate's bytes and carries
  the re-derived clean install and import sweep, which the promote job repeats itself.
- **Alternatives considered:** (a) promote 73e67a2e as it stands -- impossible, the refusal is in
  the verifier the workflow runs from the tagged tree; (b) a manual record for 73e67a2e -- refused
  by design, TestPyPI holds its exact bytes and the verifier then insists on the automated path;
  (c) a same-timestamp re-cut to keep the bytes -- impossible, `mixle/_build_provenance.json`
  embeds the source commit.
- **Evidence:** run 34094030813 job "Promote prepared artifacts and publish release", step
  "Re-verify immutable prepared evidence": `rehearsal record refused: record is bound to a
  different prepare run`; the record downloaded from run 34093637518 names `"prepare_run":
  "34091612593"` and the environment carried `PREPARE_RUN_ID: 34091612593`;
  `rehearsal_record_gate_test.py::test_automated_record_with_the_workflows_string_typed_prepare_run_is_accepted`.
- **Owner:** release owner.
- **Reviewer:** accepted — Grant Boquet, release owner (order given in session: "push to pypi"); 2026-09-07; https://github.com/gmboquet/mixle/actions/runs/34094030813
- **Expiration:** none.
- **Worklist:** release-checklists/0.8.2-followups.md (A-04, A-05).
