## 1. Problem statement

Fit a multilevel (mixed-effects) model to home radon measurements across Minnesota counties: estimate
the effect of measuring on the first floor versus the basement, while partially pooling 85 counties
whose sample sizes range from 1 to over 100 homes, and quantify how much of the between-county
variation soil uranium explains.

Why a probabilistic-modelling library: the counties with one measurement cannot be trusted on their
own, and pooling them all together erases real geological variation. Partial pooling is the whole
point, and hand-rolling REML/EM plus BLUPs is exactly the work a library should absorb.

## 2. Data shape

- `data/radon/radon_mn.csv`, 919 rows, 85 counties. Source: Gelman & Hill (2007), via the pymc-devs
  mirror of Gelman's radon example. Documented in the dataset's `SOURCE.md`.
- Fields: `county` (category, 85 levels, heavily imbalanced), `floor` (0/1), `log_radon` (numeric
  response), `Uppm` (county-level numeric predictor).
- Unusual: severe group-size imbalance (many singleton counties) -- the case partial pooling exists
  for. A county-level predictor (`Uppm`) that is constant within group, which is what makes the
  within/between decomposition and the ecological-fallacy discussion meaningful.
- **Data-prep convention worth documenting:** the shipped CSV encodes `log(activity + 0.1)`, while
  Gelman & Hill use `log(max(activity, 0.1))`. This is why the fit lands on 1.492/-0.663/0.312/0.725
  rather than the textbook 1.46/-0.69/0.33/0.76. Inverting the transform and refitting under the book's
  convention reproduces the published numbers exactly. **The estimator is exonerated; the difference is
  the dataset.** Non-mixle OLS shows the identical shift.

## 3. Chosen model

```python
m = Normal(free * Field('floor') + free + Group('county'), free).fit(
        y, given={'floor': floor, 'county': county})
```

Four lines from CSV to a fitted varying-intercept model. Arrived at directly from the formula algebra;
`Group(...)` for the random intercept, `Field(...)` for the fixed effect. Extended in the same notebook
to varying slopes (`Group('county', slopes=['floor'])`), a county-level predictor, and a three-level
nesting attempt.

**Verified correct against two independent implementations.** An independently written profile-likelihood
LMM in pure scipy (no mixle) reproduces mixle to four decimals: intercept 1.4920, floor −0.6625,
τ 0.3118, σ 0.7254. `statsmodels` MixedLM, run for real in an isolated venv, gives the same estimates.
mixle's EM lands on the true ML optimum (`converged=True`, 55 iterations, `termination_reason='tolerance'`).
The BLUP shrinkage identity was checked from scratch across all 85 counties: mixle's `group_effects`
equal the analytic precision-weighted shrinkage to max |diff| 1.03e-08. Fixed-effect standard errors
match an independent GLS covariance exactly.

`explain_fit()` was not needed; the formula algebra was self-explanatory. The docs did *not* answer the
questions raised in §4.

## 4. Failure points

**CRITICAL — the entire model-comparison surface crashes on any regression-shaped model.** Reproduced
directly against the candidate:

```
aic(y)                    -> AttributeError: 'NoneType' object has no attribute 'dist_to_encoder'
bic(y)                    -> AttributeError: 'NoneType' object has no attribute 'dist_to_encoder'
log_likelihood(y)         -> AttributeError: 'NoneType' object has no attribute 'dist_to_encoder'
plugin_log_likelihood(y)  -> AttributeError: 'NoneType' object has no attribute 'dist_to_encoder'
compare([a, b], y)        -> AttributeError: 'NoneType' object has no attribute 'dist_to_encoder'
```

Origin: `mixle/ppl/core.py:2145-2149`, where `lower(self, target='dist')` returns `None` and the caller
dereferences it. **Scope, measured precisely:** these all work correctly for plain distributions --
`compare([p, q], d)` on two Gaussians returns a proper loglik/AIC/BIC table -- and break the moment any
`Field(...)` term appears, with or without `Group`. That is the whole regression / GLM / mixed-effects
family.

**HIGH — the error message directs the user into the crash.** `waic()`/`loo()` raise:

> "Bayesian pointwise log likelihood is unavailable for this point-estimate artifact; use
> `plugin_log_likelihood(data)`, AIC, or BIC instead."

All three recommendations are exactly the calls that crash.

**HIGH — `compare()` hangs indefinitely on a plausible misuse.** `compare(fitted_model, data)` -- a
fitted model passed positionally where a list is expected -- produced no output and no error for over
60 seconds (killed by alarm; independently reproduced). The correct call is `compare([model], data)`.
A silent infinite hang is worse than a `TypeError`.

**HIGH — `predict()` cannot score new rows.** The signature is `predict(n=1, rng=None)`: a
posterior-predictive *sampler*, not prediction at new covariates. There is no supported way to score
new data for a mixed model, so the notebook rebuilds the linear predictor by hand
(`c['intercept']['mean'] + c['floor']['mean']*x + ge.get(county, 0.0)`) in three separate cells. The name
collides with the universal regression meaning of `predict`.

**HIGH — no REML.** `fit()` exposes `how/max_its/delta/backend/num_workers/engine/precision/print_iter/missing`
but no `reml=`. mixle reports ML; lme4 -- the natural alternative -- defaults to REML, so anyone
cross-checking against `lmer` sees an unexplained third-decimal difference (τ 0.312 vs 0.3148) with no
switch to reconcile it.

**MEDIUM — `result.tau` silently reports only the first random-effect SD** when the random structure is
multidimensional. On the varying-slope model `tau=0.3330` is just the intercept SD; the slope SD (0.3160)
and the intercept–slope correlation (−0.374) live only in `random_cov`.

**MEDIUM — one grouping factor only, and the refusal comes late.** `Group('A') + Group('B')` *constructs*
successfully and fails deep inside `_lmm_fit` with `NotImplementedError`. `Group('county/region')` accepts
lme4 nesting syntax as a literal column name.

**MEDIUM — the fit outputs and the model methods live on different objects** with no cross-reference:
`coefficients/tau/sigma/group_effects/random_cov` on `m.result`, but `aic/bic/predict/compare` on `m`.

**LOW —** `result.acceptance_rate` is exposed (`None`) on a deterministic EM fit: an MCMC concept leaking
through a shared result base class.

**Environment gap (not a mixle defect):** `pandas` is required by every application notebook but is not a
mixle dependency, so a clean candidate venv cannot run them until pandas is installed.

## 6. Did mixle reduce or increase work? **Mixed — and both halves matter**

**Where it reduced work (real, measured):**

- Versus **PyMC/Stan**, its clearest win: 4 lines and 0.08 s against roughly 15–25 lines (coords, priors,
  a non-centred offset, likelihood, `sample()`, then R-hat/ESS/divergence checks). For a point-estimate
  multilevel fit this is a substantial reduction.
- Versus **statsmodels MixedLM**: parity. 4 lines each, 0.08 s vs 0.06 s, identical estimates.
- Versus **lme4**: mixle is modestly *more* work -- `lmer(log_radon ~ floor + (1|county))` is one
  expression, where mixle needs operator algebra plus a parallel `given={}` dict that names each column
  twice.

**Where it increased work (the finding that matters):** everything *after* the fit. Because the entire
model-comparison surface crashes on regression models, the notebook hand-rolls roughly **40 lines of
cross-validation** across two cells to do model comparison that should be a one-line IC call, and there
is no likelihood-ratio path to test whether a random slope earns its parameters. Because `predict()`
cannot score new rows, the linear predictor is rebuilt by hand in three more cells. That is more
boilerplate reintroduced than the fitting API removed, for this notebook's actual scope.

**Verdict:** for *fitting*, mixle is at parity with statsmodels and well ahead of PyMC/Stan. For the
full modelling workflow on this task, it **increased** total work, because model comparison and
prediction are broken for exactly the model family it advertises.

## Addendum — 2026-08-22: both defects resolved, and the gate closed

This intake is retained exactly as written on 2026-08-20. What happened afterwards:

- **Both critical defects are fixed** at commit `20021e34` (D-0191): `lower()` no longer returns `None`
  for a conditional fit — it raises — and the model-comparison surface reports a real marginal
  log-likelihood per group instead of leaking an `AttributeError`; `compare(model, data)` now rejects a
  bare `RandomVariable` before it can hang. Regression tests pin both. The reviewed candidate
  `d797eae5` is therefore superseded by the fix, as D-0191 records.
- **A third defect came out of the same corpus run** (D-0192, commit `7245effa`): the Dask planner
  started a Bokeh dashboard for the client mixle itself creates, whose teardown raises inside a running
  event loop. Fixed in the library, not worked around in the notebook.
- **The full corpus was then run against the fixed code**: 131/131 notebooks execute end to end.
- **E14.4 is closed on this evidence** under the rule amended the same day (D-0194), with the limit
  stated on the record: the *data* is external, the *user* is not, so nothing here evidences
  discoverability or legibility to a reader who did not write the library.
